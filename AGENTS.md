# PromptAgents: правила совместной работы

Прочитайте `TASK.md`, `docs/api-contract.md` и своё задание в `docs/tasks.md`.
Это пятичасовой хакатон. Этапы трёх инженеров объединены в `main`:
подбор, интерфейс и объяснения работают. Необязательный CLI для AI-подготовки
реализован, но реальный артефакт без ключа не создавался. Таблица ниже сохраняет
первоначальные зоны ответственности для дальнейших правок.

- Сохраняйте чужие изменения, корневое HTML-превью и исходный CSV без изменения байтов.
- Не заменяйте отсутствующий каталог фиктивными данными. Фикстуры — только `tests/fixtures/`.
- Фильтры и порядок — код, AI — только предварительная подготовка. Без ключа должен работать baseline.
- Любое утверждение в объяснении должно иметь evidence. Не обещайте итоговую цену по цене «от».
- Структурированные поля важнее description/AI. Противоречивый текст не подтверждает соответствие.
- Не ослабляйте условия заказа. Даты вне 2026-09-23 — 2026-12-31 дают 422.
- Ошибка данных — 503; незавершённая функция — 501, не пустой успешный ответ.
- Не добавляйте бронирование, авторизацию, платежи, БД или агентные фреймворки.
- Общие контракты меняет №1 после согласования. Работайте в отдельных `codex/...` ветках.

| Владелец | Файлы |
| --- | --- |
| №1 | `backend/app/` кроме `explanations.py`; `backend/requirements*`, общие конфиги, `AGENTS.md`, `docs/api-contract.md`, `docs/examples/`, `docs/tasks.md`, `README.md`; интеграция |
| №2 | `frontend/`, включая `src/contracts.ts` (синхронизация с контрактом №1) |
| №3 | `backend/app/explanations.py`, `scripts/`, `tests/`, `data/derived/`, `docs/demo.md` |

Команды из корня после установки зависимостей (Python 3.11, Node 24.15):

```bash
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
python -m scripts.validate_data
python -m scripts.check_demos
python -m pytest -q
npm --prefix frontend ci
npm --prefix frontend run dev
npm --prefix frontend run build
```

Используйте Python виртуального окружения `.venv`. Подробные команды Windows/Linux — README.
Отчёт о проверках должен различать реальные данные, тестовые фикстуры и непроверенные сценарии.
