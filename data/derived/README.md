# Необязательные подготовленные AI-признаки

Артефакт `features.json` **не создан**: при проверке 2026-09-23 ключа не было,
настоящие вызовы модели не выполнялись. JSON из тестов — явно тестовые ответы,
они создаются во временных каталогах pytest и не поставляются как AI-данные.
Без этого файла `explain()` работает в детерминированном режиме `baseline`.

## Генерация

Из корня проекта в активированном `.venv`:

```bash
python -m scripts.extract_features --help
python -m scripts.extract_features --model <точный-snapshot-YYYY-MM-DD> --limit 1
python -m scripts.extract_features --model <точный-snapshot-YYYY-MM-DD> --overwrite
```

Угловые скобки — плейсхолдер, замените его доступным вашей учётной записи
snapshot модели с поддержкой Structured Outputs. Скрипт не выбирает модель
или стоимость за пользователя. Альтернатива `--model` — `OPENAI_MODEL`.
`OPENAI_API_KEY` задаётся через окружение или локальный `.env` (уже исключён Git).
Не передавайте ключ аргументом командной строки и не коммитьте его.

Например, настройки локального `.env`:

```dotenv
OPENAI_API_KEY=<ваш ключ, только локально>
OPENAI_MODEL=<точный snapshot модели>
```

Настройки относятся только к необязательному CLI; baseline их не требует.
Используются уже установленные `httpx` и `pydantic`, новых зависимостей нет.
Названия окружения для CLI предложены инженеру №1; общий `.env.example`
и backend-конфигурация в этой ветке не изменяются.

`--limit 1` обрабатывает первый профиль и создаёт **частичный** артефакт;
для остальных профилей останется baseline. Полная команда без `--limit`
обрабатывает весь каталог, независимо от его размера. Замена существующего
файла требует `--overwrite`. Не запускайте повторно без необходимости:
каждый запрос к модели может тарифицироваться, кеша и автоматических retries нет.

## Провайдер, проверка и происхождение

Провайдер: OpenAI Responses API (`https://api.openai.com/v1/responses`).
Применён `text.format` с JSON Schema, согласно
[официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
На каждый профиль отправляется его анонимизированная запись и фиксированный
промпт; никаких файлов окружения, истории заказов или соседних профилей.
В запросе `store=false`, редиректы не выполняются. Не используйте этот CLI
для персональных данных без отдельной проверки разрешений и условий провайдера.

Промпт: `scripts/prompts/features-v1.txt`. В метаданные попадают:

- `schema_version=1.0.0` и `prompt_version=features-v1`;
- SHA-256 **точных байтов** исходного CSV;
- SHA-256 отправленного UTF-8 текста промпта (переносы нормализованы в LF);
- `openai/<snapshot>` из ответа, который обязан совпасть с запрошенным;
- время завершения в ISO-8601 UTC;
- исходные строковые ID и только прошедшие проверку признаки.

Разрешены `format_specialization` и `distinctive_detail`, максимум восемь
кандидатных признаков на профиль. Цитата должна быть точной, непустой,
релевантной структурированному формату и не менять условий заказа.
Проверяется также окружающее предложение: нельзя вырезать предшествующее «не».
Для специализации нужна поддерживаемая явная формулировка; для детали —
дословное `value` внутри цитаты. Реклама, неопределённость, чужая специализация,
упоминания цен, чисел, языка, длительности, календаря и города отбрасываются.
Сомнительный смысл не пытаемся исправить или пересказать.

Это консервативная проверка русскоязычных формулировок, а не универсальный
анализ смысла. Некоторые истинные признаки будут отклонены. Корректный
пустой список признаков допустим; «подготовлено» не означает бонус каждому.

Ошибки транспорта, 401/429/5xx, отказ, незавершённый ответ, неверная схема,
дубликаты ключей JSON или смена модели завершают команду без нового артефакта.
Существующий файл сохраняется. Публикация атомарная после полного прохода.
Отсутствие ключа: код завершения 2, понятное сообщение, ни файла, ни вызова API.
Частично успешный проход при ошибке провайдера не публикуется.

## Подключение backend

Чтение и проверка артефакта — зона инженера №1. Его `prepared.py` из
`codex/backend-matching` проверен совместно с этим кодом на коммите `827848c`.
По умолчанию файл — `data/derived/features.json`; после подготовки перезапустите
backend, так как артефакт читается при старте. Отсутствие/устаревание/повреждение
дают baseline с `diagnostics.warnings`, а не отказ подбора.

Экстрактор и `explain()` используют `explanations.feature_issue()`; загрузчик
№1 имеет собственную проверку. Рекомендация №1: согласовать/переиспользовать
общий консервативный валидатор, чтобы правила рекламы и контекста не расходились
при последующих изменениях. Общие модели и API-контракт не менялись.

После интеграции обязательны две отдельные команды:

```bash
python -m pytest -q
python -m pytest -q tests/integration_cases.py
```

Режим `prepared` и изменение ранжирования проверены только на явно тестовых
фикстурах. Совместимость с настоящим ответом провайдера и качество извлечения
по всему CSV ещё требуют запуска с разрешённым ключом.
