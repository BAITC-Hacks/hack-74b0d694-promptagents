# Frontend: передача инженеру №1

Ветка `codex/frontend`, база `1384354`. Изменения ограничены `frontend/`.
Контракт v1.0.0 сохранён. Дополнительных зависимостей нет, lock-файл сохранён.

## Запуск

Из корня репозитория, Node.js 24.15 (для тестов нужен Node с type stripping):

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
npm --prefix frontend test
npm --prefix frontend run build
```

Обычный режим: `http://127.0.0.1:5173/`. Vite перенаправляет `/api` на порт 8000.
Нужны существующие GET health, GET options и POST recommend по общему контракту.

## Что реализовано

- Форма использует глобальные категории из options: «Астана + Декоратор» можно
  выбрать. Необязательные параметры передаются как null.
- Повторная отправка и редактирование отменяют текущий запрос. AbortController
  и номер запроса не позволяют устаревшему ответу заменить актуальный.
- Три бизнес-исхода показаны отдельно от HTTP 422/503/501, сетевой ошибки и тайм-аута.
- Карточки (до трёх) показывают исходное explanation, цену «от», все флаги,
  происхождение и раскрываемые evidence. Ранжирование frontend не выполняет.
- Отображаются eligible_count, total_candidates, серверное message, все этапы
  диагностики, предупреждения, режим объяснений и версия данных.
- Сравнение дат доступно только для одинаковых нормализованных условий и версии
  данных. Занятость подтверждается busy_profiles + точной датой в evidence.value;
  исчезновение из top-3 не считается доказательством занятости.
- Баннер незавершённого подбора зависит от health.recommendation_implemented.
  После успешного recommend health обновляется; есть повторная загрузка при ошибке.

## Учебные примеры

Явное включение: `http://127.0.0.1:5173/?examples=1` или ссылка внизу страницы.
Примеры основаны на `docs/examples/responses.json`, дополнительные вымышленные
варианты показывают три карточки, флаги, prepared и ошибки. Везде видна метка
«Тестовые данные». Галерея загружается отдельным JS-чанком; в обычном режиме
она не подменяет ответы. Переключения на примеры при сбое сервера нет.

Демокнопки реальной формы содержат только шесть входных запросов. Они всегда
обращаются к POST /api/recommend и не используют ответы галереи.

## Проверено при сдаче

- `npm ci` и production build — успешно.
- 17 Node-тестов: API-параметры, HTTP-ошибки, отсутствие автоподмены данными,
  отмена, тайм-аут, условия сравнения дат и проверка календарных доказательств.
- В браузере все шесть реальных демокнопок заполнили ожидаемые параметры и
  получили честный 501 от backend каркаса. В сценариях 4/6 язык и длительность
  сбрасываются, глобальный список категорий сохраняется.
- В явно учебном режиме проверены matched/category_absent/no_match,
  HTTP 422/503/501, сетевые ошибки, метки происхождения, базовый/prepared-режим,
  evidence и сравнение дат с подтверждённой занятостью.
- При ширинах viewport 390 и 320 px проверена адаптация и отсутствие
  горизонтального переполнения карточек; при 320 px также проверена форма.
- Клавиатура: Enter раскрывает evidence и запускает демокнопку, Tab переводит
  фокус с города на дату; фокус виден. Нулевой бюджет отклоняется клиентом.

Полная доступность со скринридером и всеми браузерами не аудирована.
Медленный устаревший успешный ответ не эмулировался в браузере; отмена транспорта
проверена тестом, дополнительно используется счётчик актуальности ответа.

## Что осталось для интеграции

1. Интегрировать эту ветку и готовые backend/объяснения в рабочую ветку №1.
2. Сохранить схему ответа из docs/api-contract.md и выставить
   recommendation_implemented=true после готовности настоящего подбора.
3. Повторить шесть демокнопок через рабочий API: на момент проверки backend
   возвращал 501. Успешные результаты реального каталога и объяснения через API
   ещё не проверены. Учебные примеры не являются такой проверкой.
4. Повторить тесты и сборку, проверить сообщения о 1–2 результатах и смене даты
   на двух запросах с ведущими. Изменений backend-конфигурации для frontend не требуется.
