# Backend: реализация подбора

Ветка `codex/backend-matching`, API v1.0.0 без изменений схем.
`POST /api/recommend` возвращает HTTP 200 с `matched`, `category_absent`
или `no_match`; health сообщает `recommendation_implemented=true`.
Ошибки запроса остаются 422, ошибки каталога — 503.

## Реализовано

- CSV загружается при старте целиком. Проверяются заголовки, записи, типы,
  словари, уникальность ID и календарь; ошибка блокирует весь каталог.
  Парсинг и SHA-256 используют один снимок точных байтов, описание сохраняется.
- `app.matching.recommend(catalog, request, features=None, *, explainer=None)` —
  чистая функция. После города и категории применяются фильтры busy, budget,
  format, language, duration. Исключения считаются ровно один раз.
- Порядок: `(-specialization, price_from_kzt, id)`, строковое сравнение ID.
  Ответ содержит до трёх карточек, общее число подходящих, причины исключения,
  календарное evidence занятых профилей и происхождение каждой карточки.
- `app.prepared.load_features(path, catalog)` проверяет схему, хеш каталога,
  версию промпта `features-v1`, формат хеша промпта, модель, UTC-время, ID,
  формат мероприятия и цитаты. Ошибка метаданных отключает артефакт целиком;
  неподтверждённые признаки отбрасываются по одному с предупреждением.
  Отсутствие файла или AI-ключа не мешает подбору.

API вызывает `app.explanations.explain(profile, request, features)` после
фильтрации. Только пока эта функция поднимает `NotImplementedError`, используется
`app.temporary_explanations.explain` с двумя фактическими предложениями и evidence
из полей. Об этом явно сообщается в `diagnostics.warnings`, режим — `baseline`.
Остальные исключения модуля объяснений не маскируются. Временный модуль не
использует AI-признаки для текста, даже если они повлияли на порядок.

## Проверка смысла prepared-признаков

Это ограниченный детерминированный валидатор, не универсальная модель понимания
текста. Для специализации принимаются явные утверждения от первого лица:
«Специализируюсь на проведении корпоративных мероприятий»,
«Специализируемся на свадьбах», «Я свадебный фотограф» и близкие формы,
перечисленные в `app/prepared.py`. Одного названия формата недостаточно.
Проверяется и контекст предложения, чтобы нельзя было вырезать отрицание
или выдать утверждение другого человека за специализацию профиля.

Для `distinctive_detail` требуется упоминание формата и дословное вхождение
value в цитату. Пересказы не принимаются. Цитаты с отрицаниями, неоднозначностью,
неподдерживаемыми форматами или упоминанием структурированных условий
(языка, города, цены, часов, чисел, занятости) консервативно отбрасываются.
Даже часть верных цитат может быть отброшена; причина видна в warnings.
Никакие признаки не расширяют условия заказа или поля профиля.

он ожидает `recommendation_implemented=false` и HTTP 501. Файл принадлежит №3
и не изменён. Остальные тесты, включая ошибки CSV и запросов, проходят.
