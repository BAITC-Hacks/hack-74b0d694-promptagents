# PromptAgents — умный подбор подрядчиков для мероприятий

## 2. Краткое описание: для кого и зачем

Организатору свадьбы, корпоратива или другого события сложно вручную сопоставить
десятки подрядчиков по городу, свободной дате, бюджету и условиям работы.
PromptAgents принимает параметры мероприятия, показывает до трёх подходящих
профилей и объясняет каждый выбор фактами из каталога. Проект создан для
заказчиков мероприятий в Казахстане. Полное условие хакатона — [TASK.md](TASK.md).

## 3. Что реализовано

- Форма заказа: город, категория, дата, формат и бюджет; язык и длительность
  необязательны. Значения выбора загружаются из `GET /api/options`.
- Детерминированный подбор по структурированным полям CSV: город и категория,
  затем занятость, стартовая цена, формат, язык и длительность.
- До трёх карточек с ценой «от», объяснением, раскрываемыми источниками
  доказательств (`evidence`) и отметками синтетических/восстановленных данных.
- Три отдельных исхода: `matched` — есть подходящие, `category_absent` — нет
  категории в городе, `no_match` — категория есть, но условия не прошёл никто.
  Показаны общее число подходящих и причины исключений.
- Шесть демокнопок с реальными параметрами. Они отправляют запрос в API;
  ожидаемые ответы в приложение не встроены.
- Сравнение двух дат при одинаковых остальных условиях. Сообщение о занятости
  конкретного профиля опирается на его календарь в ответе API.
- Обработка загрузки, ошибок валидации и сервера, мобильная компоновка и
  отдельно помеченный режим учебных примеров `?examples=1`.

## 4. Как работает решение

1. Заказчик задаёт параметры события в форме или выбирает демокнопку.
2. Frontend отправляет `POST /api/recommend`. Backend проверяет запрос и
   загруженный при старте каталог.
3. Алгоритм последовательно исключает неподходящих кандидатов, ранжирует
   оставшихся по подтверждённой специализации, стартовой цене и ID.
4. Пользователь получает до трёх карточек, число всех подходящих, объяснения
   с доказательствами и диагностику исключений. При отсутствии результата
   видит причину, а не пустой экран.

Например, запрос «Алматы · ведущий · 10 октября 2026 · корпоратив · бюджет
1 000 000 ₸ · русский · 6 часов» даёт **4 подходящих** и показывает первые
**3 карточки**. При смене даты на 11 октября состав меняется по проверенному
календарю. Полные результаты шести сценариев — в [docs/demo.md](docs/demo.md).

## 5. Технологии

| Часть | Технологии |
| --- | --- |
| Интерфейс | React 19.3, TypeScript 7, Vite 8, CSS, Node.js и npm |
| API и алгоритм | Python 3.11, FastAPI 0.115.12, Pydantic 2.11.5, Uvicorn |
| Данные | Стандартный `csv.DictReader`, UTF-8 с возможным BOM; каталог в памяти, без БД |
| Тесты | pytest 8.3.5, HTTPX 0.28.1, встроенный тестовый раннер Node.js |
| Необязательная AI-подготовка | Отдельный CLI через OpenAI Responses API; модель задаётся точным snapshot в `OPENAI_MODEL` |

FastAPI загружает и проверяет CSV, отдаёт настройки формы и подбирает до трёх
подрядчиков. Город и категория, занятость, бюджет, формат, язык и длительность
проверяются по структурированным полям. Ранжирование учитывает явные пожелания,
подтверждённую специализацию, стартовую цену и ID. Ответ различает `matched`,
`category_absent` и `no_match`, показывает число всех подходящих и причины
исключений. Каждая карточка содержит объяснение и проверяемые evidence.

## 6. Архитектура проекта

`React → Vite proxy /api → FastAPI → каталог CSV в памяти → фильтры и рейтинг →
объяснение с evidence → ответ API → карточки и диагностика`.

В API v1.1 добавлены необязательные `preferences_text` и `preferences`, а в форму —
пожелания по выбранной категории. У ведущего показываются подача и взаимодействие
с гостями, у зала — терраса, вид и парковка. Карточки различают совпадения,
противоречия и недостаток сведений, показывают точные цитаты и разбор оценки.
Дата, бюджет, язык и длительность из текста не подменяют поля формы.
Две дополнительные демокнопки показывают влияние пожеланий на реальном запросе.

Формула: `(-preference_score, -specialization, price_from_kzt, id)`.
Каждый заданный критерий даёт +1 / −1 / 0, вес всегда 1; повторения не учитываются.
Неизвестное и неоднозначное — 0, а не минус. Без пожеланий preference_score=0.
Это эвристика соответствия заказу, не психологический тест и не оценка человека.
Все жёсткие фильтры выполняются раньше ранжирования.

Свободный текст разбирается фиксированными правилами с LRU-кэшем и стабильным
хешем интерпретации. Версии данных, признаков и правил возвращаются в API.
Нераспознанные пожелания не приписываются пользователю. Проверка описаний
консервативна: часть корректных формулировок остаётся unknown. Имена, пол, возраст,
национальность, семейные и психологические характеристики не используются.
Утверждения из описания обозначены как заявления подрядчика.
Два запроса, точный словарь и результаты проверок — [docs/preferences.md](docs/preferences.md).

## Технологии и архитектура

Модели запросов и ответов — в `backend/app/models.py`, контракт — в
[docs/api-contract.md](docs/api-contract.md). Изменение CSV или подготовленного
артефакта требует перезапуска backend.

Браузер → Vite proxy `/api` → FastAPI → проверенный CSV в памяти. Модуль подбора
выполняет фильтры и ранжирование, затем вызывает `explain()` для карточек.
Объяснения работают без AI. Необязательный offline-скрипт может подготовить
признаки через OpenAI Responses API в `data/derived/`; при HTTP-запросе к модели
обращений нет. Новый `scripts.extract_preferences` сохраняет признаки пожеланий
отдельным файлом на профиль с версиями модели/промпта и хешами. В этой проверке
после разрешения пользователя реальный API вернул HTTP 401: настроенный ключ
не прошёл аутентификацию. AI-артефакты не созданы; успешное извлечение проверено
на тестовых ответах, а резервный режим — также после реального отказа API.
Приложение работает по полям и точным цитатам локального режима.

Нужны Python 3.11 и Node.js 24.15.0 (npm 11.12.1); команды выполняются из
корня репозитория. Исходный CSV уже включён, конвертация не нужна.

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m scripts.validate_data
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Во втором терминале:

```powershell
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run dev
```

### Linux / macOS

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
.venv/bin/python -m scripts.validate_data
.venv/bin/python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
```

Открыть [форму](http://127.0.0.1:5173), [health](http://127.0.0.1:8000/api/health)
или [Swagger](http://127.0.0.1:8000/docs). Vite направляет `/api` на порт 8000.
Файл `.env` необязателен: значения по умолчанию работают с исходным CSV.
Если нужно задать другой файл, используйте `DATA_PATH`; для подготовленных
признаков — `DERIVED_PATH`. Пример переменных есть в `.env.example`.

## 8. Как проверить решение

Самый короткий повторяемый сценарий для жюри:

1. Запустите оба сервера по инструкции выше и откройте форму.
2. Нажмите первую демокнопку: Алматы, ведущий, 10.10.2026, корпоратив,
   1 000 000 ₸, русский, 6 часов. Ожидается `matched`, **4 подходящих** и
   карточки `HK-88430`, `HK-29829`, `HK-27222`.
3. Откройте `evidence` карточки: значения города, цены, формата, языка и
   календаря должны соответствовать исходному профилю.
4. Нажмите вторую демокнопку с датой 11.10.2026. Ожидаются 4 подходящих,
   первая тройка `HK-44923`, `HK-27222`, `HK-44733`; изменение занятости
   объясняется календарём. Четвёртый подходящий не превращается в карточку.
5. Для двух различных пустых исходов проверьте демокнопки «Астана + Декоратор»
   (`category_absent`) и «Алматы + Ведущий + 12.12.2026» (`no_match`).

Оставшиеся сценарии, полные множества ID и причины исключений приведены в
[docs/demo.md](docs/demo.md). Для автоматической проверки из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
.\.venv\Scripts\python.exe -X utf8 -m pytest -q tests/integration_cases.py
.\.venv\Scripts\python.exe -X utf8 -m scripts.validate_data
.\.venv\Scripts\python.exe -X utf8 -m scripts.check_demos
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
Invoke-RestMethod http://127.0.0.1:8000/api/health
Invoke-RestMethod http://127.0.0.1:8000/api/options
.\.venv\Scripts\python.exe -X utf8 -m scripts.verify_api_demos
```

На Linux/macOS используйте `.venv/bin/python` и `npm` вместо команд Windows.
Последняя проверка объединённого проекта (23.09.2026): **95** обычных Python-тестов,
**36** интеграционных, **17** frontend-тестов, успешная production-сборка,
66 валидных профилей и **6 из 6** реальных HTTP-сценариев с ожидаемыми
результатами. Отдельно проверены страница на `:5173` и запросы через Vite proxy:
health и подбор возвращают 200. Тесты frontend и HTTP-прогон проверяют код и
API; браузерный E2E-прогон не завершён. Ожидаемый health:
`dataset_status=ready`, `profile_count=66`, `recommendation_implemented=true`.
Неверный запрос даёт 422, отсутствующий или повреждённый CSV — 503.

При недоступном системном npm-кеше на Windows используйте локальный:
`npm.cmd --prefix frontend ci --cache .npm-cache`. Папка исключена из Git.

## 9. Данные и интеграции

Исходный [hackathon dataset anonymized .csv](<hackathon dataset anonymized .csv>)
сохранён без изменения байтов. Импорт: UTF-8 с возможным BOM, разделитель списков
`|`, флаги только `True`/`False`, цена — целое число, пустой `max_hours` → `None`,
описание сохраняется дословно.
SHA-256: 6a724b6b7dfb5973343e68ba18dadb60fc807d87e3d78f03ee86fb26cb089f7d.

Подтверждены 66 уникальных профилей: Алматы — 50, Астана — 15, Зарубежье — 1;
13 synthetic, 18 price_imputed, 8 city_imputed; 13 записей с несколькими
категориями и 9 с пустым max_hours. Это характеристики текущего файла, а не
ограничения будущего размера. Дополнительных профилей в каталог не добавлено.

Структурированные поля имеют приоритет: description и AI не могут расширить
форматы, языки, длительность, изменить календарь или цену. Противоречивая цитата
не подтверждает соответствие. Внешний API используется только необязательным
offline-скриптом; [инструкция AI-подготовки](data/derived/README.md).

## 10. Ограничения

- Реальные AI-артефакты не подготовлены; без них работают локальные правила и baseline.
- Подготовленные признаки и бонус специализации проверены на тестовых ответах,
  но не на реальном вызове модели.
- Доступность подтверждается только внутри 2026-09-23 — 2026-12-31.
- Цена стартовая: окончательную стоимость нужно уточнять у подрядчика.
- Исходные синтетические и восстановленные значения помечены в карточках.
- Подробности браузерной проверки и автоматических прогонов — в docs/preferences.md.
- Изменение файла требует перезапуска backend; бронирование, авторизация,
  платежи, админка и БД не входят в объём проекта.
