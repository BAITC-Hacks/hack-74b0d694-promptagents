# Проверенные демосценарии

Источник: корневой `hackathon dataset anonymized .csv`, 66 профилей.
SHA-256: `6a724b6b7dfb5973343e68ba18dadb60fc807d87e3d78f03ee86fb26cb089f7d`.

Все шесть сценариев проверены независимым алгоритмом
`python -m scripts.check_demos`, тестами движка и реальными HTTP-запросами.
Проверенная связка: backend №1, frontend №2 и объяснения №3 в объединённой
локальной `main`. Повторный HTTP-прогон после слияния прошёл; опубликованный
сайт и браузерный сценарий этой проверкой не подтверждаются.
В runtime нет ожидаемых ID: они только в тестах и документации.
Формула baseline: (0, price_from_kzt, id), потому что подготовленных признаков нет.
После добавления подтверждённой специализации состав подходящих останется тем
же, но порядок top-3 может измениться.

## Подтверждённые объяснения состава

1. В первых двух запросах проходят по четыре профиля; интерфейс должен сообщить
   это число и показать первые три по формуле, а не объявить, что найдено только три.
2. HK-88430 и HK-29829 свободны 10 октября и заняты 11 октября.
   HK-44923 и HK-44733 заняты 10 октября и свободны 11 октября.
   Наличие/отсутствие каждой даты проверено непосредственно в busy_dates.
   Другие изменения ранга нельзя автоматически называть занятостью.
3. В Алматы всего два флориста, оба проходят условия. Поэтому карточек две.
   У обоих max_hours=None — длительность не исключает. Это не обещание
   неограниченной работы на площадке. HK-90001 — синтетика организаторов,
   HK-39372 имеет price_imputed=True.
4. В Астане нет декораторов: отдельное состояние category_absent, без подмены города.
5. Из 10 ведущих 9 заняты 12 декабря; оставшийся не принимает корпоратив.
   Это no_match, а не отсутствие категории и не ошибка сервера.
6. Из 7 залов 5 заняты, ещё 1 исключён по стартовой цене; остаётся HK-64395.

Новых синтетических профилей для демо не требуется и не добавлено.

## Фактическая проверка 2026-09-23

Windows, Python 3.11, зависимости из существующего lock-файла; AI-ключ и
derived-файл отсутствуют. SHA-256 исходного CSV после работы не изменился.

| Проверка | Результат |
| --- | --- |
| `python -m pytest -q` в объединённой main | 95 passed |
| `python -m pytest -q tests/integration_cases.py` в объединённой main | 36 passed |
| `python -m scripts.validate_data` | 66 уникальных профилей, ожидаемые частоты и флаги, ошибок нет |
| `python -m scripts.check_demos` | Шесть ожидаемых полных множеств, диагностика и baseline-порядок |
| `python -m scripts.verify_api_demos --base-url http://127.0.0.1:8014` | Шесть реальных POST к объединённой main, все HTTP 200; без mock |
| `npm --prefix frontend test` и `npm --prefix frontend run build` | 17 тестов и production-сборка прошли |
| `python -m scripts.extract_features` без ключа | Выход 2, понятное сообщение, файл не создан |

Pytest выдаёт одно предупреждение о deprecated alias `BlockingPortal`
в установленном Starlette/AnyIO; падений, skip и xfail нет.
95 тестов включают объяснения/evidence и обработку **тестовых** ответов AI API.
36 дополнительных проверок запускаются отдельной командой: имя
`integration_cases.py` не попадает в обычный сбор pytest. Они проверяют
`matching.py`, `prepared.py` и `create_app(data_path, derived_path)`.
Ожидание заглушки 501 убрано из общего health/options-теста; интеграционный
набор строго требует готовность в health и HTTP 200 от подбора.

Полные множества подходящих проверены именно функцией движка `recommend`:
каждый исходный профиль прогоняется через неё в одноэлементном каталоге,
затем отдельно проверяются общий `eligible_count` и top-3 полного каталога.
Условия фильтров в этом тесте не переписываются. Также проверены равенства
границ цены/длительности, null, нормализация, стабильная строковая сортировка
ID, перестановка исходного каталога, сумма исключённых без двойного счёта,
422 вне окна, 503 при плохом CSV, календарные evidence, флаги происхождения,
отсутствующий/повреждённый/устаревший derived, отбрасывание неподтверждённой цитаты.

Замеры последнего прогона после слияния: последовательные запросы к уже запущенному
локальному Uvicorn, один HTTP-клиент, измерение до получения ответа, без
времени запуска процесса. Это одиночный smoke-прогон, не нагрузочный benchmark.

| Сценарий | HTTP | Исход | Подходящих | Время, мс |
| --- | --- | --- | --- | --- |
| 1 | 200 | matched | 4 | 5,45 |
| 2 | 200 | matched | 4 | 2,83 |
| 3 | 200 | matched | 2 | 2,20 |
| 4 | 200 | category_absent | 0 | 1,73 |
| 5 | 200 | no_match | 0 | 1,88 |
| 6 | 200 | matched | 1 | 1,78 |

Top-3 совпали с таблицей выше. Во всех ответах `explanation_mode=baseline`;
объяснения и точные значения evidence сверены с CSV. Календарные доказательства
сверены с полными списками занятости, не выведены из исчезновения карточки.
Стартовая цена не обещает итоговый бюджет; null max_hours не обещает
неограниченную работу. Сомнительная/рекламная цитата пропускается, остаются поля.

Настоящие AI-вызовы **не выполнялись** и `data/derived/features.json` не создан.
Режим prepared, его evidence и бонус специализации проверены на явно тестовом
каталоге и ответе провайдера, не на сгенерированных признаках реального CSV.
Инструкция CLI: [data/derived/README.md](../data/derived/README.md).

## Повторение проверки

В активированном окружении из корня объединённой версии:

```bash
python -m pytest -q
python -m pytest -q tests/integration_cases.py
python -m scripts.validate_data
python -m scripts.check_demos
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале с тем же окружением:

```bash
python -m scripts.verify_api_demos --base-url http://127.0.0.1:8000
```

HTTP-проверка сверяет baseline-порядок, поэтому для неё нужен запуск без
derived-файла (при необходимости №1 задаёт `DERIVED_PATH` на отсутствующий
тестовый путь). Не удаляйте готовый AI-артефакт ради этой проверки.

После объединения осталось проверить шесть запросов в обычном браузерном UI,
карточки/evidence и сравнение дат. Такой E2E и deployed-версия **не проверялись**;
успешный HTTP-прогон не подменяет проверку интерфейса.
