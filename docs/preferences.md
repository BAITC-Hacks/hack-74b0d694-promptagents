# Подбор с пожеланиями: реализация и проверка

Ветка `codex/preference-matching`, контракт v1.1.0. Исходный CSV, HTML-превью и
66 профилей сохранены. Жёсткие условия и три бизнес-исхода не менялись.

## Что меняется

Пожелания задаются текстом или выпадающими списками для выбранной категории.
Мягкие критерии меняют только порядок прошедших все фильтры кандидатов.
Поля формы имеют приоритет; упоминания даты, бюджета, города, языка или часов
в тексте вызывают просьбу проверить условия, а не молчаливое изменение.
Нераспознанная часть текста не оценивается. Интерпретация показана пользователю.

Порядок: сумма пожеланий по убыванию → подтверждённая специализация → цена → ID.
Вес критерия 1; совпадение +1, явно заявленная другая альтернатива −1, unknown 0.
Если описаны обе альтернативы, доминирующий стиль неизвестен: тоже 0.
Это эвристика соответствия конкретному запросу. Она не измеряет качество,
надёжность, личность или вероятность успеха. Импровизация не доказывает
экстраверсию, ненавязчивость не доказывает спокойствие, цена не доказывает качество.

| Категория | Машинные критерии | Значения |
| --- | --- | --- |
| Ведущий / ведущий церемонии | delivery | calm / energetic |
| То же | formality | formal / informal |
| То же | improvisation | yes / no |
| То же | guest_engagement | active / unobtrusive |
| То же | program_focus | business / entertainment |
| Фотограф | photo_style | reportage / posed |
| Фотограф | photographer_presence | unobtrusive / active |
| Флорист / декоратор | decor_style | minimal / lush |
| Флорист / декоратор | custom_concept | yes / no |
| Зал / площадка / ресторан / отель | terrace, panorama, parking | yes / no |

Каждая характеристика подтверждается полным исходным предложением, подходящим
категории. Проверяются отрицания и противоречия структурированным данным.
Один критерий учитывается один раз. Длинное описание не приносит баллов само
по себе. Спорные формулировки пропускаются. Для услуг, не входящих в словарь,
мягкие критерии не выдумываются. Два предложения объяснения дополняются списками
matched/conflicting/unknown, evidence и доступным для проверки score_breakdown.

## Воспроизводимость и AI

В запросе нет внешней модели. Свободный текст → фиксированные правила → кэш
из 512 нормализованных интерпретаций; извлечение цитат также кэшируется.
API возвращает хеш CSV, снимка признаков, интерпретации и версию сортировки.
При неизменных данных, артефактах и правилах повтор возвращает тот же порядок.

Необязательный CLI сохраняет проверенные предложения модели по одному файлу
на профиль. Один и тот же валидатор используется для результата модели и
локального извлечения. Это консервативный резервный режим, не имитация AI.
Подготовка и ограничения описаны в [data/derived/README.md](../data/derived/README.md).
После явного разрешения пользователя запущена подготовка всего каталога.
Первый реальный запрос получил HTTP 401: настроенный ключ не прошёл
аутентификацию. AI-файлы не созданы; успешная генерация настоящих артефактов
остаётся непроверенной. Тестовые AI-ответы не попадают в runtime-каталог.
Для продолжения нужен действующий OPENAI_API_KEY в локальном `.env`, затем
повторный запуск `python -m scripts.extract_preferences` и перезапуск backend.

## Два реальных запроса

Общие поля: Алматы, Ведущий, корпоратив, 2026-10-10, бюджет 1 000 000 ₸,
русский язык, 6 часов. Отличается только preferences_text.
Полные тела запросов: [preference-requests.json](examples/preference-requests.json).

| Пожелание | Первые три ID в локальном режиме | Подходящих |
| --- | --- | ---: |
| Ненавязчивая подача | HK-77838, HK-88430, HK-29829 | 4 |
| Только развлечения и танцы | HK-29829, HK-88430, HK-27222 | 4 |

В первом запросе HK-77838 получает +1 по guest_engagement за цитату:
«Профессиональный ведущий с интеллигентной, располагающей и ненавязчивой подачей.»
Во втором HK-29829 получает +1 по program_focus: «Только развлечения и танцы.»
Это заявления из description, не независимая оценка подрядчиков.
Оба запроса оставляют то же множество подходящих:
HK-88430, HK-29829, HK-27222, HK-77838. Четыре занятых и два дорогих исключены
раньше ранжирования; AI или пожелания вернуть их не могут.

Для повторения через запущенный API:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.verify_preferences
```
